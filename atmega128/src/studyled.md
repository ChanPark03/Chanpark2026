# ATmega128 LED Study Guide

이 문서는 `led2.c`, `led3.c`, `led4.c`, `main.c`를 처음 배우는 사람도 이해할 수 있도록 자세히 설명한 학습 노트입니다.

ATmega128에서 LED를 제어할 때 가장 먼저 익혀야 하는 핵심은 아래 3가지입니다.

1. `DDRC`는 C 포트의 방향을 정하는 레지스터이다.
2. `PORTC`는 실제로 핀에 어떤 값을 내보낼지 정하는 레지스터이다.
3. `while(1)`은 전원이 켜져 있는 동안 계속 반복 실행되는 무한 루프이다.

## 1. 먼저 알아야 하는 기본 개념

### 1-1. 포트란?

마이크로컨트롤러의 핀들은 보통 묶음으로 관리됩니다.  
예를 들어 `PORTC`는 C 포트에 속한 핀들(`PC0`, `PC1`, `PC2`, `PC3` ...)을 의미합니다.

### 1-2. `DDRC`는 무슨 뜻인가?

`DDRC`는 `Data Direction Register C`의 줄임말입니다.  
이 레지스터는 C 포트의 각 핀이 입력인지 출력인지 정합니다.

- 비트 값이 `1`이면 출력
- 비트 값이 `0`이면 입력

예를 들어:

```c
DDRC = 0x0F;
```

`0x0F`는 2진수로 `00001111`입니다.  
즉,

- `PC0` 출력
- `PC1` 출력
- `PC2` 출력
- `PC3` 출력
- 나머지는 입력

이 뜻입니다.

### 1-3. `PORTC`는 무슨 뜻인가?

`PORTC`는 C 포트에 실제로 어떤 전압 값을 출력할지 정합니다.

- 비트가 `1`이면 HIGH(보통 5V에 가까운 값)
- 비트가 `0`이면 LOW(0V)

예를 들어:

```c
PORTC = 0x0F;
```

이 값은 `00001111`이므로 `PC0~PC3`에 HIGH를 출력합니다.

```c
PORTC = 0x00;
```

이 값은 모든 비트를 LOW로 만들어 LED를 끄는 효과를 냅니다.

### 1-4. `_delay_ms(500)`는 무엇인가?

```c
_delay_ms(500);
```

이 코드는 500밀리초, 즉 0.5초 동안 잠시 기다리라는 뜻입니다.

LED를 켰다가 바로 끄면 사람 눈에는 변화가 잘 안 보일 수 있습니다.  
그래서 중간에 지연 시간을 넣어 LED가 켜지고 꺼지는 것을 눈으로 확인할 수 있게 합니다.

### 1-5. `while(1)`은 왜 쓰는가?

```c
while(1)
{
    ...
}
```

`1`은 항상 참이기 때문에, 이 반복문은 끝나지 않습니다.  
임베디드 프로그램은 보통 한 번 실행되고 끝나는 것이 아니라, 계속 동작해야 하므로 무한 루프를 자주 사용합니다.

## 2. `led2.c` 해석

### 원본 코드

```c
#include <avr/io.h>
#include <util/delay.h>

int main()
{
    DDRC= 0x0F;
    while(1)
    {
        PORTC = 0x0F;
        _delay_ms(500);

        PORTC = 0x00;
        _delay_ms(500);
    }
    return 0;
}
```

### 줄별 설명

```c
#include <avr/io.h>
```

ATmega128에서 제공하는 입출력 관련 레지스터 이름(`DDRC`, `PORTC`, `PC0` 등)을 사용하기 위해 필요한 헤더입니다.

```c
#include <util/delay.h>
```

`_delay_ms()` 함수를 사용하기 위한 헤더입니다.

```c
int main()
```

프로그램이 시작되는 진입점입니다.

```c
DDRC = 0x0F;
```

C 포트의 하위 4비트(`PC0~PC3`)를 출력 모드로 설정합니다.  
보통 LED 4개를 연결했다면 이 4개의 핀을 제어할 수 있게 됩니다.

```c
while(1)
```

LED 동작을 계속 반복합니다.

```c
PORTC = 0x0F;
```

하위 4비트를 모두 `1`로 만들어 LED 4개를 켭니다.

```c
_delay_ms(500);
```

0.5초 대기합니다.

```c
PORTC = 0x00;
```

하위 4비트를 모두 `0`으로 만들어 LED를 끕니다.

```c
_delay_ms(500);
```

다시 0.5초 대기합니다.

### 이 코드가 하는 일

`led2.c`는 가장 기본적인 LED 깜빡이기 예제입니다.  
LED 4개를 동시에 켰다가, 동시에 끄는 동작을 반복합니다.

### 초보자 포인트

- `DDRC`를 먼저 설정하지 않으면 LED가 원하는 대로 동작하지 않을 수 있습니다.
- `PORTC`는 출력값을 주는 레지스터입니다.
- `0x0F`는 `00001111`이므로 하위 4비트만 사용한다는 의미입니다.

## 3. `led3.c` 해석

### 원본 코드

```c
#include <avr/io.h>
#include <util/delay.h>

int main()
{
    unsigned char led_data = 0x00;

    DDRC = 0x0F;
    while (1)
    {
        PORTC = led_data;
        led_data++;
        if(led_data > 0x0F)
            led_data = 0;
        _delay_ms(500);
    }
    return 0;
}
```

### 핵심 아이디어

이 코드는 LED를 단순히 켜고 끄는 것이 아니라, `0`부터 `15`까지 값을 1씩 증가시키며 포트에 출력합니다.

즉 다음과 같이 변합니다.

- `0000`
- `0001`
- `0010`
- `0011`
- `0100`
- ...
- `1111`
- 다시 `0000`

이 과정에서 LED 패턴이 계속 바뀝니다.

### 줄별 설명

```c
unsigned char led_data = 0x00;
```

LED에 출력할 값을 저장하는 변수입니다.  
`unsigned char`는 1바이트 크기이고, 0부터 255까지 저장할 수 있습니다.

여기서는 하위 4비트만 사용할 것이므로 실제로는 `0~15` 사이의 값만 의미 있게 사용합니다.

```c
DDRC = 0x0F;
```

`PC0~PC3`를 출력으로 설정합니다.

```c
PORTC = led_data;
```

현재 `led_data` 값을 C 포트에 출력합니다.

예를 들어:

- `led_data = 0x03`이면 `00000011`
- `PC0`, `PC1`은 켜지고
- `PC2`, `PC3`는 꺼집니다

```c
led_data++;
```

다음 패턴으로 넘어가기 위해 값을 1 증가시킵니다.

```c
if(led_data > 0x0F)
    led_data = 0;
```

`0x0F`는 10진수 15입니다.  
하위 4비트만 쓰므로 15보다 커지면 다시 0으로 되돌립니다.

```c
_delay_ms(500);
```

패턴이 너무 빨리 바뀌지 않도록 0.5초 기다립니다.

### 이 코드가 하는 일

`led3.c`는 4비트 카운터처럼 동작합니다.  
즉, LED 상태가 2진수 숫자처럼 0에서 15까지 증가합니다.

예를 들어 LED가 4개라면:

- `0000` -> 모두 꺼짐
- `0001` -> 첫 번째 LED만 켜짐
- `0010` -> 두 번째 LED만 켜짐
- `0011` -> 첫 번째와 두 번째 LED 켜짐

이런 식으로 패턴이 계속 바뀝니다.

### 초보자 포인트

- `unsigned char`는 LED 패턴 저장용으로 자주 쓰이는 자료형입니다.
- LED의 켜짐/꺼짐을 숫자의 비트로 생각하면 이해가 쉬워집니다.
- `0x0F`로 제한하는 이유는 4개의 LED만 사용하기 때문입니다.

### 코드에서 눈여겨볼 점

현재 파일에는 주석과 들여쓰기가 조금 섞여 있지만 동작 원리는 단순합니다.  
특히 `if`문은 아래처럼 중괄호를 쓰는 습관을 들이면 초보자가 실수를 줄일 수 있습니다.

```c
if (led_data > 0x0F)
{
    led_data = 0;
}
```

## 4. `led4.c` 해석

### 원본 코드

```c
#include <avr/io.h>
#include <util/delay.h>

int main()
{
    uint8_t current_pattern_value;
    uint8_t next_pattern_value = 0x01;

    DDRC = 0x0F;
    while (1)
    {
        current_pattern_value = next_pattern_value;
        
        PORTC = current_pattern_value;
        
        next_pattern_value = current_pattern_value << 1;
        if (next_pattern_value == 0x10)
        {
            next_pattern_value = 0x01;
        }
        _delay_ms(500);        
    }
    return 0;
}
```

### 핵심 아이디어

이 코드는 LED가 한 칸씩 이동하는 패턴을 만듭니다.

출력 순서는 다음과 같습니다.

- `0001`
- `0010`
- `0100`
- `1000`
- 다시 `0001`

즉 LED 하나만 켜진 상태가 왼쪽 또는 오른쪽으로 이동하는 것처럼 보입니다.

### 줄별 설명

```c
uint8_t current_pattern_value;
```

현재 출력할 패턴을 저장하는 변수입니다.  
`uint8_t`는 8비트 부호 없는 정수형으로, `unsigned char`와 비슷하게 생각해도 됩니다.

```c
uint8_t next_pattern_value = 0x01;
```

다음에 출력할 초기 패턴을 `00000001`로 설정합니다.  
즉 처음에는 첫 번째 LED만 켜집니다.

```c
current_pattern_value = next_pattern_value;
```

다음 패턴 값을 현재 패턴 변수로 복사합니다.

```c
PORTC = current_pattern_value;
```

현재 패턴을 실제 포트에 출력합니다.

```c
next_pattern_value = current_pattern_value << 1;
```

왼쪽 시프트 연산입니다.  
예를 들어:

- `0001 << 1` -> `0010`
- `0010 << 1` -> `0100`
- `0100 << 1` -> `1000`

즉 LED가 한 칸씩 이동하는 것처럼 보입니다.

```c
if (next_pattern_value == 0x10)
{
    next_pattern_value = 0x01;
}
```

`0x10`은 2진수로 `00010000`입니다.  
이 값은 이미 4개의 LED 범위를 벗어난 상태입니다.

그래서 범위를 벗어나면 다시 `0x01`로 되돌려 처음부터 반복합니다.

```c
_delay_ms(500);
```

패턴 이동 속도를 눈으로 볼 수 있도록 0.5초 대기합니다.

### 이 코드가 하는 일

`led4.c`는 한 개의 LED만 켜진 상태를 차례로 이동시키는 예제입니다.  
LED 러닝 패턴, 시프트 패턴, 이동 패턴의 기본이라고 볼 수 있습니다.

### 초보자 포인트

- `<< 1`은 비트를 왼쪽으로 한 칸 미는 연산입니다.
- 쉬프트 연산은 임베디드에서 매우 자주 사용됩니다.
- 특정 비트만 켜고 싶을 때 아주 유용합니다.

## 5. `main.c` 해석

### 원본 코드

```c
#include <avr/io.h>
#include <util/delay.h>

int main()
{
    *(volatile uint8_t *)(0x14) = 0x03;
    DDRC = 0x03;

    while (1)
    {
        PORTC |= (1 << PC0) | (1 << PC1) | (1 << PC2) | (1 << PC3);
        PORTC |= _BV(PC0) | _BV(PC1) | _BV(PC2) | _BV(PC3);
        PORTC |= _BV(PC2);
        PORTC = 0x0F;
        _delay_ms(500);

        PORTC = 0x00;
        _delay_ms(500);
    }
    return 0;
}
```

### 이 파일에서 중요한 점

이 파일은 LED를 켜는 여러 표현 방식을 한 번에 보여주려는 예제로 보입니다.  
그래서 실제 동작에 꼭 필요하지 않은 코드도 들어 있습니다.

### 줄별 설명

```c
*(volatile uint8_t *)(0x14) = 0x03;
```

이 코드는 메모리 주소 `0x14`에 직접 `0x03` 값을 저장합니다.

초보자 관점에서는 이렇게 이해하면 됩니다.

- 특정 하드웨어 레지스터 주소에 직접 접근하는 방식
- `volatile`은 컴파일러가 이 값을 마음대로 최적화하지 못하게 하는 키워드
- 레지스터를 이름이 아닌 주소로 직접 다루는 저수준 방식

다만 초보자에게는 `DDRC = 0x03;`처럼 레지스터 이름을 쓰는 방식이 훨씬 읽기 쉽습니다.

```c
DDRC = 0x03;
```

`PC0`, `PC1`만 출력으로 설정합니다.  
2진수로 보면 `00000011`입니다.

그런데 아래 코드에서는 `PC2`, `PC3`도 사용하고 있으므로, 학습 목적이라면 `0x0F`가 더 자연스럽습니다.

```c
PORTC |= (1 << PC0) | (1 << PC1) | (1 << PC2) | (1 << PC3);
```

이 코드는 `PC0~PC3` 비트를 1로 설정합니다.

여기서 `1 << PC0`는:

- `1`을 `PC0` 위치만큼 왼쪽으로 이동
- 예: `PC2`면 `00000100`

즉 각 비트 위치에 맞는 마스크를 만들어 OR 연산으로 켜는 방식입니다.

```c
PORTC |= _BV(PC0) | _BV(PC1) | _BV(PC2) | _BV(PC3);
```

이 코드는 위와 거의 같은 의미입니다.  
`_BV(bit)`는 `1 << bit`를 더 읽기 쉽게 만든 매크로입니다.

예를 들어:

```c
_BV(PC2)
```

는 사실상

```c
(1 << PC2)
```

와 같은 의미입니다.

```c
PORTC |= _BV(PC2);
```

이 줄은 `PC2`만 추가로 켜는 코드입니다.  
하지만 바로 다음 줄에서 `PORTC = 0x0F;`를 하므로 사실상 이 줄의 효과는 덮어써집니다.

```c
PORTC = 0x0F;
```

결국 이 줄이 최종적으로 `PC0~PC3`를 모두 켭니다.

```c
PORTC = 0x00;
```

모두 끕니다.

### 이 코드가 실제로 하는 일

앞부분에 여러 가지 비트 조작 예제가 들어 있지만, 최종적으로는 `led2.c`처럼 LED를 모두 켰다가 모두 끄는 동작을 반복합니다.

즉 실질적인 최종 동작은:

1. LED 4개 켜기
2. 0.5초 대기
3. LED 4개 끄기
4. 반복

### 초보자 포인트

- `|=`는 기존 값을 유지하면서 특정 비트만 켜고 싶을 때 사용합니다.
- `_BV(bit)`는 비트 마스크를 만들 때 자주 사용하는 매크로입니다.
- 레지스터 직접 주소 접근은 가능하지만, 처음에는 `DDRC`, `PORTC` 같은 이름 기반 접근이 더 이해하기 쉽습니다.

### 정리하면

`main.c`는 "LED 제어 방법 여러 개를 소개하는 연습용 예제"에 가깝습니다.  
실제 깔끔한 코드로 정리하면 다음처럼 더 단순하게 쓸 수 있습니다.

```c
#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRC = 0x0F;

    while (1)
    {
        PORTC = 0x0F;
        _delay_ms(500);

        PORTC = 0x00;
        _delay_ms(500);
    }
}
```

## 6. 네 파일의 차이 한눈에 보기

### `led2.c`

가장 기본적인 깜빡이기 예제입니다.  
LED 여러 개를 동시에 켜고 동시에 끕니다.

### `led3.c`

0부터 15까지 증가하는 4비트 카운터 패턴입니다.  
LED를 숫자처럼 다룹니다.

### `led4.c`

한 개의 LED가 이동하는 시프트 패턴입니다.  
비트 이동 연산을 배우기 좋습니다.

### `main.c`

비트 연산, `_BV()`, 직접 주소 접근 같은 여러 문법을 섞어 놓은 학습용 예제입니다.

## 7. 이 예제들로 배우는 핵심 문법

### 7-1. 16진수

- `0x00` = 0
- `0x01` = 1
- `0x0F` = 15
- `0x10` = 16

임베디드에서는 비트 상태를 보기 쉬워서 16진수를 자주 사용합니다.

### 7-2. 비트 연산

#### OR 연산 `|`

특정 비트를 켜는 데 자주 씁니다.

```c
PORTC |= _BV(PC2);
```

이 코드는 다른 비트는 그대로 두고 `PC2`만 1로 만듭니다.

#### 왼쪽 시프트 `<<`

비트를 왼쪽으로 이동시킵니다.

```c
1 << PC2
```

결과는 `00000100`이 됩니다.

### 7-3. 무한 루프

```c
while (1)
```

임베디드 시스템은 계속 동작해야 하므로 거의 항상 사용됩니다.

## 8. 초보자를 위한 공부 순서

아래 순서대로 보면 이해가 훨씬 잘 됩니다.

### 1단계: `led2.c`

먼저 가장 단순한 ON/OFF를 이해합니다.

확인할 것:

- `DDRC`가 왜 필요한가
- `PORTC = 0x0F`가 무슨 뜻인가
- `_delay_ms(500)`가 왜 필요한가

### 2단계: `led3.c`

다음으로 숫자가 증가하면서 LED 패턴이 어떻게 바뀌는지 봅니다.

확인할 것:

- 숫자와 비트 패턴의 관계
- `led_data++`의 의미
- `if(led_data > 0x0F)`가 왜 필요한가

### 3단계: `led4.c`

그 다음 비트를 이동시키는 개념을 배웁니다.

확인할 것:

- `<< 1`이 정확히 무엇을 하는가
- `0x01`, `0x02`, `0x04`, `0x08` 패턴이 어떻게 바뀌는가
- 범위를 벗어나면 왜 다시 `0x01`로 돌아오는가

### 4단계: `main.c`

마지막으로 여러 표현 방식을 비교하며 문법을 익힙니다.

확인할 것:

- `PORTC = 0x0F`와 `PORTC |= _BV(PC0)`의 차이
- `_BV()`가 왜 편한가
- 직접 주소 접근 방식이 무엇인가

## 10. 자주 헷갈리는 부분

### Q1. `DDRC`와 `PORTC`는 왜 둘 다 필요한가?

`DDRC`는 핀의 역할을 정합니다.  
`PORTC`는 그 핀에 실제로 어떤 값을 보낼지 정합니다.

즉,

- `DDRC` = 출력할 준비
- `PORTC` = 실제 출력값

이라고 생각하면 됩니다.

### Q2. 왜 `0x0F`를 많이 쓰는가?

LED 4개만 연결했다면 하위 4비트만 사용하면 되기 때문입니다.  
`0x0F`는 `00001111`이라서 딱 4개의 비트를 켤 수 있습니다.

### Q3. `_BV(PC2)`는 외워야 하는가?

많이 쓰이므로 익숙해지면 좋습니다.  
뜻은 "PC2 위치의 비트만 1로 만든 값" 정도로 이해하면 충분합니다.
